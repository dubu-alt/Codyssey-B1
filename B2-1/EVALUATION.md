### Q1. add/list/search/summary/export/import/update/delete가 요구사항대로 동작하는가?

**확인 방법**: 위 시연 스크립트 그대로 실행.

- [ ] `add`: 대화형 입력으로 저장되고 id 출력됨
- [ ] `list`: 최신순, `--limit` 동작
- [ ] `search`: 조건 조합(`--from`, `--category` 등) 동작
- [ ] `summary`: 총수입/총지출/잔액 + TOP N 출력
- [ ] `export`/`import`: 처리 건수 출력됨
- [ ] `update`/`delete`: 성공/실패 메시지 구분됨

### Q8. 코드가 3개 이상 모듈로 분리되어 있다. 각 모듈의 책임을 "어떻게" 나눴는가?

**모범답변 포인트** (본 프로젝트 기준):

## 그룹 3. 원리 이해 · 근거 설명

### Q11. list/search를 제너레이터로 스트리밍 처리한 방식을 "어떻게" 구현했고, "왜" 유리한가?

**모범답변 포인트**:
- 구현: storage.py에서 파일을 `for line in f`로 **한 줄씩 읽고 yield**로 Transaction을 하나씩 넘김. 리스트에 다 쌓지 않음
- 장점: 메모리 사용량이 파일 크기와 무관하게 일정(O(1)). 10만 줄짜리 파일에서 `list --limit 5`를 해도 앞 5건만 읽고 멈출 수 있음
- 함수에 `yield`가 있으면 Python이 자동으로 제너레이터로 만든다는 점

**꼬리질문 추천**: "list --limit 5면 파일 몇 줄을 읽나요?" → 최신순이라 역방향 접근이 필요한 경우를 제외하고 필요한 만큼만 읽는 게 이상적. 제너레이터의 지연 실행(lazy) 개념을 알고 있는지 확인.

- [ ] 통과

### Q12. 데코레이터로 분리한 공통 기능이 무엇이며, "왜" 분리가 필요했는가?

**모범답변 포인트**:
- 대상: `decorators.py`의 오류 처리 데코레이터(예외를 잡아 `[오류]`/`[힌트]` 출력 + 종료 코드 1 반환). 실행시간 측정 등이 추가로 있다면 함께 언급
- 이유: 모든 명령마다 try/except를 복붙하면 코드가 중복되고, 오류 메시지 형식이 명령마다 달라질 위험이 있음. 데코레이터 하나로 **모든 명령의 오류 처리 형식을 강제**할 수 있음

**꼬리질문 추천**: "데코레이터 없이 하려면 어땠을까요?" → 각 명령 함수마다 똑같은 try/except 복사. "한 곳 고치면 전체에 적용된다"는 관점이 나오면 통과.

- [ ] 통과

### Q13. 타입 힌트의 이점을 실제 코드 예로 "어떻게" 확인했고, "왜" 도움이 되는가?

**모범답변 포인트**:
- 실제 코드 예: `Transaction` dataclass 필드(date: str, amount: int 등)나 함수 시그니처 `def search(transactions: Iterator[Transaction], ...) -> list[Transaction]`
- 이점: (1) 에디터 자동완성과 오타 즉시 감지, (2) amount에 문자열을 넘기는 실수를 실행 전에 발견, (3) 함수가 무엇을 받아 무엇을 돌려주는지 문서 역할
- "실행해봐야 아는 버그"를 "코드 읽는 시점에 아는 버그"로 바꿔준다는 표현이 나오면 좋음

## 그룹 4. 확장 · 응용 질문

### Q14. JSONL과 CSV 중 선택한 저장 포맷의 장단점을 비교하고, "왜" 그 포맷을 택했는가? (JSONL 선택 기준)

**모범답변 포인트**:
- JSONL 장점: 한 줄에 한 레코드 → **추가(append)가 쉽고**, 태그 같은 리스트/자료형을 문자열 변환 없이 그대로 저장, 제너레이터로 한 줄씩 읽기 자연스러움
- JSONL 단점: 엑셀에서 바로 안 열림, 사람이 읽긴 약간 불편
- CSV 장점: 범용성, 엑셀 호환. 단점: 쉼표/따옴표 이스케이프 문제, 모든 값이 문자열이라 타입 복원 필요, 줄 단위 append 시 인코딩/개행 실수 위험
- 결론 근거: "프로그램 내부 저장엔 JSONL, 외부 교환(import/export)엔 CSV"라는 역할 구분이 나오면 만점

- [ ] 통과

### Q15. 거래가 10만 건으로 늘어난다면 병목은 어디이며 "어떻게" 개선할지?

**모범답변 포인트**:
- 병목: `summary`/조건 `search`는 결국 전체 파일을 한 번씩 훑어야 함(O(n)). 특정 월만 필요한데 전체를 읽는 낭비
- 개선안: (1) 월별로 파일을 나눠 저장(파티셔닝), (2) 날짜 인덱스 파일을 유지, (3) 더 큰 규모면 SQLite 같은 인덱스 내장 저장소로 이동
- 제너레이터 덕분에 list는 영향이 적다는 점까지 구분해서 말하면 좋음

- [ ] 통과

### Q16. import CSV에 일부 깨진 행이 섞이면 "어떻게" 처리해 사용자 신뢰를 지킬 것인가?

**모범답변 포인트**:
- 전체 실패(전부 롤백)보다 **부분 성공 + 리포트**가 사용자 친화적: `imported=5, skipped=2`처럼 건수를 알려주고, **몇 번째 줄이 왜** skip됐는지 목록 출력
- 깨진 행만 걸러내고 정상 행은 확실히 저장. 필요하다면 "--strict" 같은 옵션으로 전체 롤백 모드도 제공 가능
- 이미 구현된 `imported=N, skipped=N` 출력을 보여주면 가장 좋음

- [ ] 통과
