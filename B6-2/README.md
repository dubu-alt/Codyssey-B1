# AWS 클라우드 미션 개념 정리

> 비전공자를 위한 쉬운 설명서
> 이 문서는 AWS 웹 서비스 인프라 구축 미션에 나오는 개념들을 일상 비유로 풀어 설명합니다.

---

## 이 미션을 한 문장으로

> **"인터넷에서 접속되는 나만의 웹사이트 서버를, 안전하게 만들고 → 확인하고 → 깨끗이 치우기"**

집을 짓는 과정에 비유하면 이렇습니다.

| 미션 단계 | 집짓기 비유 |
|---|---|
| VPC 만들기 | 울타리 친 내 땅 확보 |
| Subnet 만들기 | 땅 안에 건물 지을 구역 정하기 |
| Internet Gateway | 대문 달기 |
| Route Table | "나가려면 대문으로" 이정표 세우기 |
| EC2 만들기 | 그 구역에 집(컴퓨터) 짓기 |
| Security Group | 현관문 잠그고 누가 들어올지 정하기 |
| Nginx 설치 | 집 안에 가게 차리기 (손님 맞이) |
| 외부 접속 확인 | 손님이 실제로 들어오는지 확인 |
| 리소스 정리 | 실습 끝나면 철거 (월세 안 나가게) |

# 1부. 네트워크 기초

## 1-1. IP 주소 — 인터넷 세상의 주소

**IP 주소**는 인터넷에 연결된 기기 하나하나의 **주소**입니다. `10.0.1.5` 처럼 숫자로 되어 있어요.

- 택배를 받으려면 집 주소가 필요하듯, 데이터를 주고받으려면 IP가 필요합니다.
- **사설 IP**: 내 울타리 안에서만 통하는 주소 (예: `10.0.1.5`) — 아파트 동·호수 같은 것
- **공인(퍼블릭) IP**: 전 세계 어디서나 찾아올 수 있는 주소 — 도로명 주소 같은 것

> **미션 연결**: EC2 서버에 **퍼블릭 IP**가 있어야 외부 사람이 브라우저로 접속할 수 있습니다.

---

## 1-2. CIDR — 주소의 "범위"를 쓰는 방법

`10.0.0.0/16` 같은 표기를 **CIDR**이라고 합니다. **주소 하나가 아니라 주소 묶음(범위)** 을 뜻해요.

**비유**: 아파트 단지 주소라고 생각하세요.

- `10.0.0.0/16` → "우리 아파트 **단지 전체**" (약 65,000개 주소)
- `10.0.1.0/24` → "그 안의 **101동**" (약 250개 주소)

뒤의 숫자(`/16`, `/24`)가 **작을수록 넓은 범위**, **클수록 좁은 범위**입니다.

**미션에서 쓰는 값**

| 값 | 의미 |
|---|---|
| `10.0.0.0/16` | 내 VPC 전체 (단지 전체) |
| `10.0.1.0/24` | Public Subnet (101동) |
| `0.0.0.0/0` | **모든 주소 = 전 세계 어디서나** |

> **중요**: `0.0.0.0/0`은 "전부"라는 뜻입니다. Route Table에서는 "모든 바깥 목적지"라는 좋은 의미지만, Security Group에서는 "누구나 들어와도 됨"이라 위험할 수 있습니다. 같은 표기라도 **어디에 쓰느냐에 따라 의미가 달라집니다.**

---

## 1-3. VPC — 내 전용 네트워크 땅

**VPC (Virtual Private Cloud) = AWS 안에 만든, 나만 쓰는 격리된 네트워크 공간**

**비유**: AWS는 거대한 아파트 단지입니다. 수많은 사람이 여기에 서버를 둡니다. 내 서버가 남의 서버와 뒤섞이면 불안하겠죠. 그래서 AWS는 **"여기부터 여기까지는 당신 땅"** 이라고 울타리를 쳐줍니다. 그게 VPC입니다.

**특징**

- 남들은 내 VPC 안을 들여다볼 수 없습니다 (격리)
- 내 서버들끼리는 울타리 안에서 자유롭게 통신합니다
- 바깥 인터넷과 연결할지 말지 **내가 직접 설계**합니다

> **왜 첫 단계일까?**
> 서버를 인터넷에 그냥 노출시키면 위험합니다. VPC는 서버를 안전한 울타리에 넣고, 문을 어디에 낼지 내가 정하게 해줍니다. 그래서 모든 것의 출발점입니다.

---

## 1-4. Subnet — 땅 안의 구역

**Subnet = VPC라는 큰 땅을 잘게 나눈 한 구역**

**비유**: 단지 안의 "101동"입니다. 실제 서버(EC2)는 VPC에 바로 놓는 게 아니라 **Subnet 안에** 놓습니다.

**두 종류**

| 종류 | 설명 | 쓰임새 |
|---|---|---|
| **Public Subnet** | 인터넷과 연결된 구역 | 웹 서버처럼 외부에서 접속해야 하는 것 |
| **Private Subnet** | 인터넷과 차단된 구역 | 데이터베이스처럼 숨겨야 하는 것 |

> **핵심**: Public/Private을 나누는 건 이름이 아니라 **Route Table에 인터넷으로 가는 길이 있느냐**입니다. 길이 있으면 Public, 없으면 Private입니다.

> **미션 연결**: 이번엔 웹 서버를 외부에 공개해야 하므로 **Public Subnet 1개**만 만듭니다.

---

## 1-5. Internet Gateway (IGW) — 바깥으로 나가는 대문

**Internet Gateway = 내 VPC와 인터넷을 이어주는 정문**

**비유**: 아무리 좋은 단지라도 **대문이 없으면** 아무도 들어올 수 없고 나갈 수도 없습니다. IGW가 그 대문입니다.

**중요한 점**

- IGW는 **만들기만 하면 안 되고, VPC에 "연결(Attach)"** 해야 작동합니다
- 대문을 사놓고 벽에 안 달면 소용없는 것과 같습니다

> **미션 연결**: IGW가 없거나 연결 안 되어 있으면 → 서버가 인터넷도 못 나가고, 외부에서 접속도 안 됩니다. "왜 안 되지?" 할 때 가장 먼저 확인할 곳입니다.

---

## 1-6. Route Table — 이정표

**Route Table = "어디로 가려면 어느 길로 가라"는 교통 이정표**

**비유**: 단지 안에 갈림길이 있습니다. 안내판이 없으면 택배기사가 헤매겠죠. Route Table이 그 안내판입니다.

**미션에서 넣는 규칙**

```
Destination(목적지)  →  Target(보낼 곳)
-------------------------------------------
10.0.0.0/16         →  local        (자동 생성)
0.0.0.0/0           →  igw-xxxxx    (내가 추가!)
```

읽는 법:

- 1번 줄: "우리 단지 안(10.0.0.0/16) 주소면 → 단지 내부에서 해결"
- 2번 줄: "그 외 **모든 곳(0.0.0.0/0)** 이면 → **대문(IGW)으로** 보내라"

> **핵심**: 이 두 번째 줄이 있어야 비로소 **Public Subnet**이 됩니다. 그리고 이 Route Table을 **Subnet에 연결(Associate)** 하는 것도 잊으면 안 됩니다.

---

## 1-7. 포트(Port) — 건물 안의 문 번호

IP가 "건물 주소"라면 **포트는 그 건물의 몇 번 문**인지를 뜻합니다.

**비유**: 같은 건물에 은행, 카페, 사무실이 있습니다. 주소는 같아도 **문 번호**로 구분하죠.

**꼭 알아야 할 포트**

| 포트 | 용도 | 미션에서 |
|---|---|---|
| **80** | HTTP (일반 웹사이트) | 누구나 열기 (`0.0.0.0/0`) |
| **443** | HTTPS (암호화 웹사이트) | 보너스 과제에서 사용 |
| **22** | SSH (서버 원격 관리) | **내 IP만** 열기 |

> **미션 연결**: "열린 포트 하나로 서버가 털린다"는 말이 여기서 나옵니다. 필요한 문만 열고, 관리용 문(22번)은 나만 쓸 수 있게 해야 합니다.

---

## 네트워크 전체 흐름 정리

외부 사용자가 내 웹사이트에 접속할 때 데이터가 지나가는 길:

```
   [ 인터넷의 사용자 ]
            |
            v
   [ Internet Gateway ]        <- 대문 통과
            |
            v
   [ Route Table ]             <- 이정표 확인
            |
            v
   [ Security Group ]          <- 문지기 검문 (80번 문 열려있나?)
            |
            v
   [ EC2 안의 Nginx ]          <- 웹페이지 응답!
```

**이 흐름을 말로 설명할 수 있으면 미션 목표의 절반은 달성입니다.**

# 2부. 서버와 보안

## 2-1. EC2 — 빌려 쓰는 컴퓨터

**EC2 (Elastic Compute Cloud) = AWS에서 빌리는 가상 컴퓨터(서버)**

**비유**: 컴퓨터를 사서 집에 두는 대신, **필요할 때 빌려 쓰고 쓴 만큼만 돈 내는** 방식입니다. 렌터카와 비슷합니다.

**만들 때 정하는 것들**

| 항목 | 뜻 | 미션 기준 |
|---|---|---|
| **인스턴스 타입** | 컴퓨터 성능 (CPU/메모리) | `t2.micro` 또는 `t3.micro` (프리티어) |
| **AMI** | 운영체제 이미지 | Ubuntu LTS 또는 Amazon Linux |
| **EBS** | 저장 공간 (하드디스크) | 8~10GiB |
| **키페어** | 접속용 전자 열쇠 | 1개 생성, 안전 보관 |

> **용어**: "인스턴스(Instance)"는 **실제로 켜진 서버 한 대**를 말합니다. EC2가 서비스 이름이라면, 인스턴스는 그 서비스로 만든 개별 컴퓨터입니다.

---

## 2-2. EBS — 서버의 하드디스크

**EBS (Elastic Block Store) = EC2에 붙는 저장 공간**

**비유**: EC2가 컴퓨터 본체라면, EBS는 그 안의 **하드디스크**입니다.

> **과금 주의**: EC2를 삭제해도 **EBS 볼륨이 남아있으면 계속 돈이 나갑니다.** 정리 체크리스트에 EBS가 들어있는 이유입니다.

---

## 2-3. 키페어 — 서버의 전자 열쇠

**키페어 = 비밀번호 대신 쓰는, 훨씬 안전한 열쇠 파일** (`.pem` 파일)

**비유**: 도어락 비밀번호는 남이 알아낼 수 있지만, **물리적 열쇠**는 복제가 어렵죠. 키페어는 그 열쇠에 가깝습니다.

**작동 방식**

- **공개키**: 서버에 저장됨 (자물쇠)
- **개인키**: 내가 다운받아 보관 (열쇠) → 이걸로 접속

> **매우 중요**
> - 개인키 파일은 **딱 한 번만 다운로드**됩니다
> - 잃어버리면 **재발급 불가** → 그 서버에 영영 못 들어갑니다
> - 절대 남에게 공유하거나 GitHub에 올리지 마세요

---

## 2-4. SSH — 서버에 원격 접속하기

**SSH = 멀리 있는 서버에 안전하게 접속해서 명령을 내리는 방법**

**비유**: 회사 컴퓨터를 집에서 원격으로 조종하는 것과 같습니다. 다만 화면이 아니라 **글자(명령어)** 로 조종합니다.

접속하면 검은 화면에 명령어를 입력하게 되는데, 여기서 Nginx를 설치하게 됩니다.

> **미션 연결**: SSH는 22번 포트를 씁니다. 그래서 Security Group에서 22번을 **내 IP에만** 열어야 접속이 됩니다. (안 열면 접속 불가, 다 열면 위험)

---

## 2-5. Security Group — 서버 앞 문지기

**Security Group (SG) = EC2 앞을 지키는 방화벽. "누가, 어느 문으로 들어올 수 있나"를 정하는 규칙**

**비유**: 건물 입구의 **경비원**입니다. 명단에 없으면 못 들어갑니다.

**두 방향**

- **인바운드(Inbound)**: 바깥 → 서버로 **들어오는** 트래픽 ← 미션에서 중요한 부분
- **아웃바운드(Outbound)**: 서버 → 바깥으로 **나가는** 트래픽 (보통 기본값 유지)

**미션 필수 규칙**

| 포트 | 허용 대상 | 이유 |
|---|---|---|
| 80 (HTTP) | `0.0.0.0/0` (누구나) | 웹사이트는 아무나 볼 수 있어야 함 |
| 22 (SSH) | **내 IP만** | 서버 관리는 나만 해야 함 |

**절대 하면 안 되는 것**

- 포트 `0-65535`를 `0.0.0.0/0`에 여는 것 → **미션 실패 조건이자 실제 해킹 위험**
- 22번을 `0.0.0.0/0`에 여는 것 → 실제로 몇 분 안에 자동 공격 시도가 들어옵니다

> **알아두면 좋은 점**: Security Group은 **"화이트리스트"** 방식입니다. 기본은 전부 차단이고, **허용한 것만** 통과시킵니다. 그래서 아무 규칙도 없으면 아무도 못 들어옵니다.

---

## 2-6. IAM — 누가 무엇을 할 수 있는가

**IAM (Identity and Access Management) = AWS 계정 안에서 "누가 어떤 작업을 할 수 있는지" 정하는 권한 관리 시스템**

**비유**: 회사 **사원증**입니다. 인턴은 창고에 못 들어가고, 팀장은 들어갈 수 있는 것처럼요.

**핵심 용어**

| 용어 | 뜻 |
|---|---|
| **루트 계정** | 회사 대표이사. 뭐든 할 수 있음 → **평소엔 쓰면 안 됨** |
| **IAM 사용자** | 일반 직원. 필요한 권한만 받음 |
| **정책(Policy)** | 사원증에 적힌 권한 목록 |
| **역할(Role)** | 잠깐 빌려 쓰는 임시 권한 |

**최소 권한 원칙 (Least Privilege)**

> **"딱 필요한 만큼만 준다"**

왜 중요할까요? 사원증을 잃어버렸을 때, **마스터키**를 잃은 것과 **창고 열쇠**만 잃은 것은 피해 규모가 완전히 다릅니다.

**미션 기준**

- EC2, VPC, Security Group 작업에 필요한 권한만
- S3, RDS 등 실습과 무관한 권한은 부여하지 않음
- **`AdministratorAccess`는 절대 부여하지 않음**

---

## 2-7. Security Group vs IAM — 헷갈리기 쉬운 차이

**미션 목표에도 나오는 중요한 구분입니다.**

|  | Security Group | IAM |
|---|---|---|
| **무엇을 통제?** | **네트워크 트래픽** | **AWS 작업 권한** |
| **비유** | 건물 **경비원** | 회사 **사원증** |
| **예시** | "80번 포트로 들어오는 접속 허용" | "이 사람은 EC2를 만들 수 있음" |
| **대상** | 데이터(패킷) | 사람/서비스 |

**한 문장 정리**

> **Security Group은 "데이터가 서버에 들어갈 수 있나"를, IAM은 "사람이 AWS에서 작업할 수 있나"를 통제합니다.**

---

## 2-8. Nginx — 웹 서버 프로그램

**Nginx (엔진엑스) = 웹페이지를 손님에게 보여주는 프로그램**

**비유**: EC2가 **가게 건물**이라면, Nginx는 그 안의 **점원**입니다. 손님(브라우저)이 오면 상품(웹페이지)을 건네줍니다.

Nginx가 없으면 서버는 켜져 있어도 아무 응답을 안 합니다. 건물은 있는데 점원이 없는 셈이죠.

**확인 방법**

```bash
curl http://localhost
```

이 명령을 서버 안에서 실행해 **200** 응답이 오면 Nginx가 잘 돌아가는 것입니다.

> **용어**: `curl`은 "이 주소로 요청 한번 보내봐" 하는 명령어입니다. `localhost`는 "나 자신(이 컴퓨터)"이라는 뜻입니다.

---

## 2-9. HTTP 상태 코드 — 서버의 대답

서버가 응답할 때 붙이는 **숫자 신호**입니다.

| 코드 | 뜻 | 느낌 |
|---|---|---|
| **200** | 성공 | "여기 있습니다!" |
| **403** | 접근 금지 | "권한이 없습니다" |
| **404** | 없음 | "그런 페이지 없는데요" |
| **500** | 서버 오류 | "저희 쪽 문제입니다..." |
| **응답 없음** | 연결 자체가 안 됨 | 방화벽/네트워크 문제일 가능성 |

> **트러블슈팅 팁**: **404가 뜨면 서버까지는 도달한 것**이고, **아예 응답이 없으면 네트워크나 Security Group 문제**일 가능성이 큽니다. 이 구분만 알아도 원인 찾기가 훨씬 쉬워집니다.

# 3부. 자주 겪는 오류와 원인 찾기

미션에 **트러블슈팅 보고서**가 있는 이유는, 오류를 겪고 해결하는 과정 자체가 배움이기 때문입니다. 아래는 흔한 상황들입니다.

## 증상별 점검 순서

### "SSH 접속이 안 돼요"

1. Security Group 22번 포트가 **내 IP**로 열려 있나?
2. 내 IP가 바뀌지 않았나? (집/카페 옮기면 IP가 달라집니다)
3. 키페어 파일 경로와 권한이 맞나?
4. 인스턴스에 **퍼블릭 IP**가 있나?

### "브라우저로 접속이 안 돼요"

1. Security Group 80번 포트가 `0.0.0.0/0`으로 열려 있나?
2. Nginx가 **실행 중**인가? (서버 안에서 `curl http://localhost` 확인)
3. Route Table에 `0.0.0.0/0 → IGW` 경로가 있나?
4. IGW가 VPC에 **연결(Attach)** 되어 있나?
5. `https://`가 아니라 **`http://`** 로 접속했나? (흔한 실수)

### "서버에서 인터넷이 안 돼요" (`curl https://example.com` 실패)

1. Route Table에 IGW 경로가 있나?
2. Route Table이 해당 Subnet에 **연결(Associate)** 되어 있나?
3. 인스턴스에 퍼블릭 IP가 있나?

## 트러블슈팅 보고서 작성 틀

미션 제출물에 필요한 형식입니다. 오류를 겪을 때마다 이 순서로 메모해두면 나중에 편합니다.

| 항목 | 적을 내용 |
|---|---|
| **증상** | 무슨 일이 일어났는가 (에러 메시지 그대로) |
| **원인 가설** | 왜 그럴 것 같은가 |
| **검증 방법** | 그 가설을 어떻게 확인했는가 |
| **조치 내용** | 무엇을 바꿨는가 |
| **결과** | 해결됐는가 |
| **재발 방지** | 다음엔 어떻게 예방할 것인가 |

# 4부. 시작 전 알아두면 좋은 것

## 돈 관련

- **프리티어**: 가입 후 12개월간 일부 자원 무료. 이 미션은 그 범위 안에서 진행합니다.
- **하지만 안 지우면 과금됩니다.** 서버를 켜둔 채 방치하거나 Elastic IP를 할당해두고 안 쓰면 요금이 발생합니다.
- **추천**: 결제 알림(Billing Alarm)을 설정해두면 요금 발생 시 이메일로 알려줍니다.

## 흔한 실수 Top 4

1. **지역(Region)을 서울로 안 바꿈** → "내가 만든 게 왜 안 보이지?" 하는 초보자 최다 실수. 화면 오른쪽 위를 항상 확인하세요.
2. **IGW를 만들고 VPC에 연결(Attach)을 안 함** → 대문을 사놓고 안 단 상태
3. **Route Table을 Subnet에 연결(Associate)을 안 함** → 이정표를 세웠는데 그 구역엔 안 세운 상태
4. **키페어 파일 분실** → 재발급 불가. 다운로드 즉시 안전한 곳에 보관하세요.

## 마음가짐

- **한 번에 안 되는 게 정상입니다.** 오류를 만나는 게 이 미션의 목적 중 하나입니다.
- **이름표(Name tag)를 붙이세요.** `mission-vpc`, `mission-ec2`처럼 정해두면 나중에 찾고 지우기 쉽습니다.
- **단계마다 확인하고 넘어가세요.** 한꺼번에 만들고 나중에 확인하면 어디가 잘못됐는지 찾기 어렵습니다.

# 5부. 스스로 점검하기

미션이 끝난 뒤 아래 질문에 **말로 답할 수 있으면** 제대로 이해한 것입니다. (미션 "과제 목표"에 해당합니다)

1. VPC, Subnet, Route Table, Internet Gateway는 각각 무슨 역할이고, 트래픽은 어떤 순서로 흐르나요?
2. Security Group과 IAM의 차이는 무엇인가요? 최소 권한 원칙은 왜 필요한가요?
3. 외부 요청이 EC2의 웹 서버까지 도달하려면 어떤 설정들이 필요한가요?
4. 오류가 났을 때 어떤 순서로 원인을 찾아나가나요?
5. 클라우드 과금은 주로 무엇 때문에 발생하고, 리소스는 어떤 순서로 정리해야 하나요?

## 참고: 리소스 정리 순서와 이유

**의존 관계 때문에 순서가 있습니다.** (붙어 있는 걸 먼저 떼어내야 지울 수 있습니다)

1. **EC2 인스턴스 종료(Terminate)** — 가장 먼저. 과금의 주요 원인
2. **EBS 볼륨 삭제** — EC2 삭제 후 남아있을 수 있음
3. **Elastic IP 반납(Release)** — 할당했다면. 안 쓰는 상태로 두면 과금됨
4. **Internet Gateway 분리(Detach) 후 삭제** — VPC보다 먼저
5. **Subnet, Route Table 삭제**
6. **VPC 삭제** — 안에 있는 걸 다 지워야 삭제됨
7. **Billing 대시보드 확인** — 남은 과금 항목이 없는지 최종 점검

## 용어 빠른 찾기

| 용어 | 한 줄 요약 |
|---|---|
| VPC | 내 전용 네트워크 땅 (울타리) |
| Subnet | 땅 안의 구역 |

| Internet Gateway | 인터넷으로 나가는 대문 |
| Route Table | "어디로 가라" 이정표 |
| EC2 | 빌려 쓰는 가상 컴퓨터 |
| 인스턴스 | 실제로 켜진 서버 한 대 |
| EBS | 서버의 하드디스크 |
| 키페어 | 서버 접속용 전자 열쇠 (재발급 불가) |

| Security Group | 서버 앞 문지기 (네트워크 방화벽) |
| IAM | 누가 무엇을 할 수 있는지 정하는 권한 |
| 최소 권한 원칙 | 딱 필요한 만큼만 권한 주기 |
| Nginx | 웹페이지를 보여주는 프로그램 |
| 포트 | 건물의 문 번호 (80=웹, 22=관리) |
| 프리티어 | 12개월 무료 사용 범위 |
